## 판독

1. **검색이 내용 커버리지를 거의 안 깎는다 (EPCov -0.013).** v1에서 paraphrase가 검색으로 0.17 깎이던 프로파일이 사라짐 — 리랭커 상시 도입 + 프롬프트 v3의 효과가 3배 규모·6도메인에서 재현. paraphrase retrieved 0.897 (oracle 0.932).
2. **multi_doc 저점의 실체 (07-18 눈검증·분해로 확정): "벡터 RAG 멀티홉 약점" 아님.**
   - 저점 케이스 분해: 검색이 문서를 못 가져온 건 retrieved에서 10건뿐 — 대부분은 컨텍스트에 있는데 인용이 안 붙은 것.
   - 그 "미인용"의 62%(37/60 문항)는 gold의 부당 기대였음: 같은 정보가 두 문서에 중복(13) / §상호참조로 단일 문서 완결(24 — 코퍼스에 심은 상호참조의 역설).
   - 보정 후 multi_doc Cite: oracle 0.783→**0.917**, retrieved 0.617→**0.817**. 잔여 갭 = 진짜 인용 생략 습관(내용은 쓰고 라벨 생략) + 검색 미스 10건.
   - 그래프 RAG 도입 근거 없음 — 우리 multi_doc은 연쇄 추론이 아닌 규정 조합이고 검색 미스율 ~8%. 실문서 대규모 유입 후 진짜 멀티홉 수요가 보이면 재검토.
   - 후속: 규칙 7에 "복수 문서 각각 인용" 지시 추가 실험 (진행 중), 검색 미스 10건은 그 후 잔차 재평가.
   - 주의: B형(상호참조 완결) 24문항은 보정 후 사실상 단일 문서 문항 — **순수 정보 분담형은 23문항**. gold v3 설계 시 multi_doc 순도 재고려.
3. **테넌트 스프레드 작음** (retrieved EPCov 0.913~0.960) — 특정 도메인 붕괴 없음. NGO(굿피플)도 이커머스와 동급 = 파이프라인의 도메인 일반성 확인.
4. **harim 구어체가 최난이도** (paraphrase 0.821, multi_turn 0.850) — 식품 도메인 관용 표현("닭이 녹아서 왔어요") 계열. 파일럿 시 실사용 표현 수집 대상.
5. **multi_turn 0.942 (n=90)** — v1 대비 4.5배 표본에서 유지. condense 경로 견고.
