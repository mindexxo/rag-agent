# 청크 경계 검증 리포트 (#245)

측정 커밋 main `77d355f`, 개발계 색인(모의 6테넌트 + 사내 실문서 + 이 PR의 합성 5건, 2026-10-18). 운영 코드·설정 변경 없음.
§1·§4는 `python -m eval.chunk_boundary`(규칙 진단, 생성 없음), §3은 합성 골드 13문항을 운영 vLLM으로 생성한 일회성 측정이다.

## 한 줄 결론

**경계는 글자를 잃지 않는다. 맥락을 잃는다.** 문장 중간이 잘려도 분할기 오버랩이 다시 실어 주고, 표는 행 단위로 묶어
자른다(#252). 하지만 뒤 조각에는 "무엇에 대한 사실인지"를 알려 주는 앞 글(목록 머리·소제목·표 설명·주석·'이 경우'의 대상)이
없을 수 있다. 사실 조각 하나만 근거로 주면 **13문항 중 6문항이 모호·오답·거절**이었다. 지금은 문서가 작아서 운영 경로의
상위 5개 근거에 맥락 조각이 같이 들어와 문제가 드러나지 않을 뿐이다.

## 1. 경계 실태 — 기존 코퍼스

`python -m eval.chunk_boundary`(정의점: `eval/chunk_boundary.py`). 같은 섹션 안 이웃 조각 경계(분할기·표 묶음이 만든 것) 166개.
아래 수치는 합성 문서(`*_18_*`)를 포함하고, XLSX는 뺀다(시트 조각은 근거 조립에서 시트 완성본으로 바뀌어 경계가 모델에 닿지 않는다).

| 경계 종류 | 건수 | 뜻 |
|---|---|---|
| sentence | 103 | 앞 조각이 문장 끝 |
| table_text | 20 | 표 ↔ 글 |
| next_item | 19 | 뒤 조각이 항목·소제목·조 제목으로 시작 |
| table_row | 9 | 표 행 사이 |
| mid_overlap | 8 | 문장 중간이지만 오버랩이 끊긴 문장을 다시 실음 |

- **골드 정답 스니펫이 경계에 걸린 것: 0 / 1,316**(조각 하나 안 1,315 · 색인에 없음 1 — 경계와 무관, 같은 도구의 `gold_snippets`). 잘림이 실제 정답을 가린 사례는 없다.
- 글자 소실 0 — 합성 TXT·MD에서 테스트로 고정(`tests/test_chunk_boundary_245.py::test_글자_소실_0`).
- 첫 실행에서 mid_cut이 5건이었는데 4건은 PDF에서 짧은 조끼리 한 섹션으로 묶여 뒤 조각이 '제 N 조(…)'로 시작하는 경우였다
  (잘림 아님) → 조 제목 판정(`rag.identifiers.is_heading_line`)을 next_item에 넣었다. 오버랩 판정은 5자 이상 일치만 인정한다
  (우연한 글자 일치 배제 — 실문서에 쉼표 조각 하나 7자짜리 진짜 오버랩이 있어 그보다 낮게 잡았다).

## 3. 답변 영향 — 합성 골드 13문항(`*_cb0NN`)

질문은 실제로 잘린 위치를 보고 "뒤 조각에 있는 사실 + 앞 조각에만 있는 맥락"을 묻게 만들었다. 정답 스니펫은 조각 하나 안에 있다
(테스트로 고정 — 스니펫이 경계에 걸리면 재는 것이 바뀐다). 생성기는 운영 vLLM.

| 조건 | 결과 |
|---|---|
| 운영 경로(prepare→generate) | 13/13 사실·맥락 조각이 모두 근거 상위 5에 듦. 답변은 harim_cb001 1건이 단위(kg당·부가세 별도) 누락, 나머지 정답 |
| **사실 조각 하나만 근거로** | **6/13 손상** — 거절 3(harim_cb001 단가 단위·homeplus_cb002 퍼밀·aromanica_cb001 보관 온도), 오답 2(goodpeople_cb002 "서면 경고"로 오인, homeplus_cb003 "전량 반품" 지어냄), 모호 1(goodpeople_cb001 조치 내용 없음) |

운영 경로가 무사한 이유는 합성 문서가 작아서(문서당 조각 3~7개) 상위 5에 형제 조각이 같이 들어오기 때문이다. 문서가 길어지거나
다른 문서와 경쟁하면 이 보호막이 사라진다 — 위 "사실 조각 하나만" 결과가 그때의 모양이다. aromanica_cb002는 문자열 채점에서
놓쳤지만 답변 자체는 정답("최소 순도 기준은 90.5%")이다.

## 4. 맥락 손실 빈도 — 기존 코퍼스

| 종류 | 합성 | 모의 | 실문서 | 판독 |
|---|---|---|---|---|
| list_label 목록 소제목 분리 | 0 | **12** | 0 | 전부 `*_08_상담스크립트모음.txt`의 '[상황 N] …' 단계 목록. TXT라 제목 경로도 비어 있어 뒤 조각은 어느 상황의 단계인지 모른다 |
| list_head 목록 머리 분리 | 1 | 0 | 2 | 실문서 2건 중 1건이 '다음 각 호' 목록 |
| reference '단,'·'이 경우'로 시작 | 1 | 0 | 4 | 실문서 '단, …' 예외 문장이 본문과 다른 조각 |
| table_lead 표 설명 | 4 | 0 | 3 | 실문서 3건은 표 앞 부칙 줄(표 설명 아님) — **오탐** |
| table_note 표 주석 | 2 | 0 | 0 | |
| table_header MD 표 머리 행 | 1 | 0 | 0 | 규칙 밖 1건 — 아래 |

- 같은 (문서, 종류, 잃은 줄)은 한 건으로 센다. 규칙이 내는 수치는 후보이고, 위 판독은 예시를 사람이 읽어 확정했다
  (예시는 `eval/results/chunk_boundary_<시각>/census.json`, gitignore — 실문서 원문 포함).
- 규칙 밖 1건: 쪽을 넘긴 PDF 표가 머리 행 없이 새 표로 인식돼(데이터 첫 행이 머리 행 자리에) 뒤 조각이 열 이름을 잃는다.
  이웃한 다른 표와 규칙으로 가를 수 없어 수치에 넣지 않았다.
- 표 앞뒤 맥락(B1·B2·B3)은 **실문서에서 0건**이다. 실제로 잦은 것은 **목록이 소제목·머리와 떨어지는 것**이다.
