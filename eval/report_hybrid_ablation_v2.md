# 하이브리드(BM25) 재도입 어블레이션 v2 — 기각 (#128)

- 측정: 2026-09-04, main `a17ad7a` 기준, gold v2+hard95 450문항(멀티턴 제외 TYPES 10종), skip 0
- 실행: `python -m eval._hybrid_ablation` (DB + TEI 임베딩·리랭커, LLM 불필요)
- 구 어블레이션(`eval/report_retrieval_ablation_v1.md`, dense-only 전환 근거)의 재측정판 —
  현행 코퍼스·현행 gold·'파일명>헤딩' 프리픽스 도입 **후** 눈금

## 결론 — 재기각. 이번엔 이론 상방이 0으로 확정

**주입 상방 = 0/450**: 정답 청크가 dense 후보 30개 밖에 있으면서 BM25 상위 30 안에 있는
문항이 하나도 없다. 하이브리드의 존재 이유(dense가 놓친 정답을 어휘 채널이 후보군에 주입)가
현행 체계에서 성립할 자리 자체가 없다 — 융합 설계를 어떻게 하든 결과는 못 바뀐다.

| variant | R@5 | Hit@1 | MRR | R@5 hard | Hit@1 hard |
|---|---|---|---|---|---|
| baseline (dense30→rerank→20) | 0.980 | 0.811 | 0.885 | 0.989 | 0.633 |
| hyb_union (dense30+bm25 주입 15→rerank) | 0.980 | 0.811 | 0.884 | 0.989 | 0.633 |
| bm25only (bm25_30→rerank) | 0.960 | 0.802 | 0.871 | 0.989 | 0.633 |
| baseline_norr (리랭크 없음) | 0.958 | 0.736 | 0.830 | 0.956 | 0.589 |
| hyb_union_norr | 0.958 | 0.736 | 0.830 | 0.956 | 0.589 |
| bm25only_norr | 0.884 | 0.593 | 0.717 | 0.867 | 0.489 |

읽는 법:
- **hyb_union ≡ baseline** — 주입된 어휘 후보는 리랭커가 전부 걸러냄(MRR −0.001 노이즈뿐).
  리랭커를 꺼도 동일(주입분이 dense 순위 뒤에 붙어 top20에 못 듦).
- **bm25only+리랭커 0.802** — 어휘 채널 단독조차 리랭커가 baseline 근처까지 끌어올린다.
  구 어블레이션의 "리랭커가 채널 차이를 흡수" 재확인. 단 paraphrase −3.3%p(어휘 채널이
  구어체를 깎는 과거 패턴 그대로).
- Hit@1 고난도 0.633은 전 변형에서 미동도 없음 — 그 병목은 구판↔개정 랭킹 역전(#123)이라
  어휘 채널과 무관함을 재확인.

## 왜 구 어블레이션보다 더 단정적인가

구판(v1)에서는 어휘 채널의 편익 증거가 1건 있었다(정확 코드 질의 rl024 — dense top5 실패,
bm25 rank2). 현행 체계에서는 그마저 사라졌다: **'파일명>헤딩' 프리픽스(8/3, Hit@1
0.703→0.784)가 임베딩에 어휘 신호를 이미 주입**해서, dense 리콜이 천장(R@5 0.980·상방 0)에
붙었기 때문으로 해석된다. 즉 "어휘 정보를 검색에 넣자"는 아이디어 자체는 유효했고,
우리는 그걸 하이브리드가 아니라 프리픽스로 이미 흡수한 상태다.

## 1차 실행의 조립 결함 (기록)

1차 실행은 가중 RRF(0.8/0.2) 융합 후 상위 30 컷 조립이었는데, dense 우세 가중에서는 어휘
전용 후보의 최고 RRF 점수(0.2/61)가 dense 꼴찌 점수(0.8/90)보다 항상 낮아 **후보 풀이
baseline과 수학적으로 동일**해진다 — 소수점 3자리까지 일치한 결과가 그 지문이었다.
측정 규율("조립을 값으로 검증한 뒤 측정")의 실사례로 남긴다. 2차(union 주입)가 본 측정.

## 재검토 트리거 (이월)

- **실코퍼스 투입 시**: 모의 코퍼스는 상품코드·고유명·신조어 분포가 빈약해 어휘 채널의
  상방이 구조적으로 과소평가된다. 파일럿 실문서에서 `주입 상방`(이 스크립트가 출력)을
  재계산해 0이 아니면 재론.
- 재도입 시 운영 구현 후보(이 순서로 검토): 앱 인메모리 BM25(파일럿 규모, 설치 0) →
  tsvector+bigram 사전토큰(내장) → pg_bigm(확장 — 관리형 PG 지원 목록 확인 선행).
- 메타데이터(카테고리 부스트)는 별도 사유로 pass(#128 코멘트) — 84문서 분류표·변별력

trgm의 유일한 고유 강점 후보(오타·문자 뭉개짐 내성)를 실측: gold 30문항 × 오타 2종

## 최종 정산 — 어휘 채널의 현재형 근거 3종 전부 0

일반 질의 구제 0/450 · 고난도 컨텍스트 변화 0 · 오타 구제 0/60. 남는 것은 "실코퍼스에선
다를 수 있다"는 가설뿐이고, 그 판정 도구(이 스크립트의 `주입 상방` 지표)는 저장소에 있다.
"정의만 있고 일하지 않는 코드를 두지 않는다"는 저장소 원칙에 따라 운영 배선(retriever
주입·플래그·테스트)은 되돌리고 **측정 자산(이 스크립트 + 본 리포트)만 남긴다**.

## 재검토 트리거 (유효)

파일럿 실코퍼스에서 `python -m eval._hybrid_ablation` 재실행 → `주입 상방 > 0`이면 재론.
그때 배선은 PR #130 이력(1ac561f)에서 복원 가능하되, 채널은 trgm이 아니라 **BM25
(1순위: PG 역색인 테이블 — 확장 불요·정본과 동일 트랜잭션 / 확장은 개발계 PG 16.14에

trgm은 어휘 채널의 실무 표준이 아니며(BM25가 표준), 오타 내성이라는 고유 가치도 이
임베딩 체계에선 불필요함이 실측됐다.

# #133 — 토크나이저 실측 비교 (bigram vs kiwi) + 재도입 설계 정본

재도입 설계 정본은 이슈 #133 본문(FTS 'simple' + df 통계 테이블 + 앱 BM25 재점수 —
토크나이저는 갈아끼우는 부품, 교체 = 재색인 1회). 여기는 그 설계의 마지막 미결 변수였던
토크나이저 선택의 실측 기록.

## 정량 (450문항, 2026-09-06, main 48bcf82)

| | 채널 단독 리콜(top30) | 주입 상방 | 최종 Hit@1 (dense+주입→리랭크) |
|---|---|---|---|
| BM25 + **bigram**(어절 내) | 96.9% (436/450) | 0 | 0.811 (= baseline) |
| BM25 + **kiwi**(내용어) | 97.6% (439/450) | 0 | 0.809 (−1문항, 노이즈) |

**차이 = 회수력 3문항(0.7%p), 최종 지표 동률.** 양쪽 다 주입 상방 0 — 이 코퍼스의 결론
(#128)은 토크나이저와 무관함도 재확인.

## 정성 (미등록어 절단 눈검증)

- **kiwi 우세**: 코드류 정밀 — 'HP-CS-011'→[hp,cs,011] (bigram은 's-','-c' 노이즈 조각),
  외래어 통짜('써머스코리아','얼리버드', 미등록 신조어도 통째)
- **bigram 우세**: **절단 결정성** — kiwi는 문맥 의존이라 같은 단어가 색인문(긴 본문)과
  질의(짧은 문장)에서 다르게 잘릴 수 있음. 실사례: '아더에러'가 문장 안에선 통째,
  단독에선 [아,더,에러]로 오분할('아로마니카'→[아로마,니,카]도). bigram은 문맥 무관
  동일 절단이라 이 위험이 원리적으로 없음

## 판정 — 기본 토크나이저 = bigram(어절 내) 확정

kiwi의 +0.7%p 회수 우위는 그 관리 비용(테넌트별 사용자 사전, 버전 고정+업 시 전체 재색인,
문맥 의존 절단 리스크)을 정당화하지 못한다. bigram은 관리 0·결정적·pg_bigm 정합.
**재평가 트리거**: 실코퍼스에서 코드·모델명류 질의 비중이 크고 bigram 노이즈 조각이 회수를
깎는 사례가 실측될 때 — 이 스크립트에 두 채널이 나란히 있어 재실행만 하면 된다.
(kiwipiepy는 eval 전용 선택 의존 — 미설치 시 kiwi 채널 자동 스킵, requirements 미등재.)

부수 개선: bigram을 어절 내 절단으로 수정(구판은 공백 제거 후 절단이라 "반품 기간"→"품기"
같은 어절 경계 가짜 조각 생성 — #133에서 교정).
