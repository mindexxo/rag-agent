# 키워드·벡터 결합 가중치 검증 (#248) — 하이브리드는 유지, 가중치는 두지 않는다

- 측정: 2026-10-18, main `43d6a65` 기준(이 PR은 eval·tests만 바꾼다 — 운영 검색 코드 무변경), 개발계 색인 캡처 1회(`hybrid_20261018_2134`)
- 질문 1,618문항 = 문장형 골드 613(`retrieval_v2`와 같은 문항·정답) + **상담원식 키워드형 420(신규 `eval/retrieval_keyword`)** + 조 번호 585(`retrieval_article`)
- 재현: `python -m eval.hybrid_weights capture` → `verify` → `diagnose` → `compare` (결과는 `eval/results/hybrid_<stamp>/`, gitignore)
- 실문서(inticube) 토큰·원문은 이 문서에 쓰지 않는다 — 저장소가 공개다. 예시는 모의 코퍼스에서만.

## 한 장 요약 (회의용)

**질문**: 다른 팀은 키워드·의미 검색을 **가중치로 섞는다**(가중 RRF, 질문 유형별 동적 비중 — 숫자·짧은 질문은 키워드 70%).
우리는 가중치 없이 "벡터 후보 + 키워드 후보 주입 → 리랭커(cross-encoder)가 순위 결정"이다. 상담원은 문장보다
**문서 속 코드·약어·전문용어를 짧게** 물을 가능성이 높다 — 그런 질의에서도 지금 구조로 충분한가, 가중치를 둬야 하나.

**결론: 하이브리드(키워드 후보 주입)는 꼭 필요하고 유지한다. 그 위에 가중치는 두지 않는다 — 넣으면 오히려 나빠진다.**

| 확인한 것 | 결과 |
|---|---|
| 상담원식 키워드 질의(코드·약어·업무 용어 420문항)를 지금 잡나 | 근거 상위 5에 정답 **99.5%** (코드 138/138, 약어 44/44, 업무 용어 236/238) |
| 키워드 검색이 실제로 일하나 | 키워드 질의에서 **BM25 단독 1위 90% vs 벡터 단독 49%**. 키워드 주입을 끄면 **23건(5.5%)이 근거에서 빠진다** |
| 가중치로 더 나아질 여지 | 정답이 리랭커 후보 풀에 못 든 문항 **0/1,618**. 키워드 후보를 100위까지 넓혀도 새로 찾는 정답 **0** |
| 가중치를 넣으면 | 후보 5개(리랭크 뒤 키워드 점수 혼합) **전부 악화, −1.1 ~ −1.5%p**(95% 신뢰구간이 모두 0 아래). 다른 팀 방식 그대로가 가장 나쁨(−1.5%p, 문장형 −3.4%p) |

**왜 이렇게 되나** — 검색은 두 단계다.

| 단계 | 하는 일 | 키워드 검색의 역할 |
|---|---|---|
| ① 후보 찾기 | 수천 조각 중 리랭커에 넘길 ~50개를 고른다 | **필요하다.** 벡터가 못 찾는 코드·용어 질의의 정답을 넣어 준다(키워드형 5.5%) |
| ② 순위 매기기 | 리랭커가 질문과 후보를 **통째로 읽고** 채점 | **불필요하다.** 리랭커가 키워드 일치를 이미 점수에 반영한다. BM25 점수를 또 섞으면 같은 신호를 두 번 세고, 구어체 질문에선 일상 단어에 끌려 틀린다 |

가중 RRF·점수 혼합은 **리랭커 없이 순위를 정할 때**의 기법이다. 리랭커가 있는 구조에서는 효과가 없는 게 정상이다 — 우리 구현 문제가 아니다(BM25 단독 성능은 키워드 질의에서 매우 좋다).

**다시 잴 조건**: 문서가 수만 조각 규모로 커질 때(벡터 상위 30이 정답을 놓치기 시작하면 키워드 주입 수가 모자랄 수 있다 — #235), 리랭커를 빼거나 바꿀 때.

## 1. 무엇을 왜 쟀나

- 기존 골드의 키워드 성격 유형(`rare_lexical` 71)은 "상품코드 AR-2003 원료의 계열이 뭐예요?" 같은 **완결된 문장**이다. 상담원식 짧은 질의는 0건이었다 — #128의 "주입 상방 0/450"도 문장형 골드의 결과라, 키워드 검색이 강한 구간을 아무도 재지 않았다.
- 그래서 키워드형 질문셋을 만들었다(`eval/retrieval_keyword.py`, 단독 실행 축으로 남김):
  - 토큰: 코드(라틴+숫자) · 영문 약어 · **복합 업무 용어**(Nori 명사 형태소가 붙은 것, 다른 회사 문서에 안 나오는 것) — 테넌트 안에서 조각 3개 이하에 나오는 것
  - 질문: 토큰만 / 토큰+뜻을 바꾸지 않는 꼬리 / "토큰 뭐야"를 번갈아, 테넌트당 60
  - 정답: 그 토큰이 든 조각 전부. 합격 = 모델이 받는 근거 상위 5의 **글**에 토큰이 있나
  - 검수 30문항(원문 대조): 1차 규칙(드문 단일 명사)은 업무 용어 2/10 — '합산'·'전체' 같은 일반어가 걸렸다. 복합어 + 다른 회사 문서에 없음으로 바꾼 뒤 코드 10/10·약어 8/10·업무 용어 9/10. 리뷰에서 가짜 약어(숫자 붙은 코드의 앞부분 'SB1000'→'SB')·버전 표기('Ver1.8')를 걸러 낸 최종판은 코드 10/10·**약어 6/10**(화면 글자 'TODAY'·요일 'MON' 같은 일반어가 빈자리를 채움)·업무 용어 7/10(조사가 붙은 '…이'·잘린 조각 3건) — 예외 규칙을 늘리지 않고 한계로 둔다. 쉬운 문항이 섞이면 가중치 이득을 **크게** 보이게 하는 쪽이라, 이득이 없다는 결론에는 보수적이다
- 판정 기준(결과를 보기 전에 고정): 주 지표 **근거 상위 5 적중(in_evidence)**, 보조 Hit@1. 후보 조건 목록도 미리 고정(`hybrid_replay.CANDIDATES`). 짝 부트스트랩 95% 신뢰구간(1만 회, 시드 고정).

## 2. 방법 — 한 번 캡처, 오프라인 재생

- 질문마다 한 번: 임베딩, 벡터 상위 30·100, BM25 상위 30·100(점수), 조 번호 후보, 후보 상위집합의 리랭커 점수. 운영 크기(30)는 따로 받았다(근사 탐색에서 100의 앞 30 ≠ 30일 수 있어서).
- 리랭커는 질문-조각 쌍을 독립으로 채점하므로, 조건(풀 구성·점수 혼합)을 바꿔도 다시 검색하지 않고 계산할 수 있다. 조건끼리 같은 점수를 써서 TEI 호출마다의 흔들림이 조건 차이에 섞이지 않는다.
- **재생 = 운영 확인** (#128 1차 측정은 조립이 틀려 기준선과 같은 값이 나왔다 — 그 재발 방지):
  - ① 운영 `retrieve_candidates`의 단계 함수를 각 문항의 캡처값으로 끼워 **실제로 돌린 결과 = 재생**: 1,618/1,618 완전 일치
  - ② 아무것도 끼우지 않은 실제 운영(표본 100) vs 재생: 완전 일치 89, 근접 동점 자리바꿈 6(어긋난 모든 자리의 리랭커 점수 차 < 0.005 — TEI 흔들림), 캡처 뒤 색인 변동 5(다른 세션의 업로드), 설명 안 되는 차이 0 (`verify.json`)
  - 재생을 일부러 망가뜨리면(중복 제거 누락·주입 상한 틀림·조 번호 주입 누락·가산 누락) ①이 실패하는지 단위 테스트로 고정(`tests/test_hybrid_replay.py`)
- 측정 중 바로잡은 것:
  - 엑셀 표는 같은 시트 조각을 가장 위 하나로 접고 시트 전체를 넘긴다 — 정답 행이 든 형제 조각이 id로는 빠져도 모델은 그 행을 본다. 조각 id로 판정하면 놓친 것으로 잘못 센다(첫 실행: 키워드 4·문장형 5건). 같은 시트면 적중으로 판정한다
  - 공유 개발계 색인이 측정 중 다른 세션의 업로드로 바뀌었다(BM25 단어 희소도는 인덱스 전체라 남의 테넌트 문서에도 점수가 움직인다). ①은 캡처값만으로 돌게 해 이 영향에서 떼어 냈다

## 5. 결론과 후속

- **하이브리드(키워드 주입 15)를 유지한다** — 상담원식 키워드 질의의 5.5%를 살린다. 이번 측정 전까지 이 효과는 어느 골드에서도 보이지 않았다.
- **가중치(가중 RRF·동적 비중·리랭크 뒤 점수 혼합)를 두지 않는다** — 풀 쪽은 원리적으로 효과 없음(풀 누락 0), 점수 쪽은 측정상 악화.
- 키워드형 질문셋(`python -m eval.retrieval_keyword`)을 단독 실행 축으로 남긴다(`retrieval_article`처럼 run_all 밖) — 문장형 골드가 못 보던 구간을 감시한다.
- 재측정 트리거: 문서 수만 조각(#235), 리랭커 교체·제거.
- 별건 후보: 표 "한 질문엔 한 시트만" 필터로 정답 시트가 밀린 2건 — 가중치와 무관, 필요 시 별도 이슈.
- 알려진 한계: 키워드형 질문은 Nori로 뽑은 토큰을 Nori BM25가 채점하므로 **BM25에 유리한 쪽으로 기운 측정**이다 — 그래도 가중치가 이득이 없다는 결론에는 보수적으로 작용한다. Nori가 명사가 아닌 품사로 잘못 자르는 용어(부사+동사로 분석되는 업무 용어가 실재한다)는 질문셋에서 빠진다.
